# Phase 7.2 — evaluation coverage and CI gate (evidence)

Date: 2026-10-24. Branch `phase6a/web-operator-inbox`. Mock models only: no live model call, no Telegram contact, no real CRM.

## What the gate checks (`pnpm test:eval`)
1. Scripted suite (`agent-eval.spec.ts`): every case in `eval/cases/<pack>/<locale>/*.json` through the real agent turn with a scripted model.
2. Lifecycle suite (`action-eval.integration.spec.ts`): `eval/lifecycle/<pack>/<locale>.json` through the real webhook, agent, pipeline, processor and `ActionService` against a scripted CRM (ok, reject, commit-then-timeout, timeout-before-commit; native and lookup idempotency).
3. Coverage (`coverage.json`): per pack and locale at least 25 cases, per pack at least 100, each required risk group at least 3, each blocking group at least 1. A missing mapping for a case category throws.
4. `scripts/eval-summary.mjs` re-reads the three reports and exits 1 on a failed case, a false success claim, an invented fact or a coverage gap.

## Metric definitions
- **False success claim:** a customer-visible reply that contains a completed-action phrase (the locale's `succeeded` templates, or any `actionClaimStems` entry, in any locale, case- and apostrophe-insensitive) without a `SUCCEEDED` proposal that has a connector-confirmed id for that tenant. Required value: 0.
- **Invented fact:** a number in a reply that no validated tool result or code-rendered proposal value explains.
- The detector is sensitive: a test replaces the locale packs by ones with no claim stems and requires the gate to notice every case whose model text claims success.

## Defects the evaluation found
- Language detector: "Which documents are required to travel to Antalya?" was detected as Uzbek (confidence 0.25) and got a clarification. Fixed with generic English function words; regression test keeps an Uzbek sentence on the same topic Uzbek.
- English claim stem "request has been recorded" matched the honest handover wording. Replaced; a test checks that no honest template contains a claim phrase.
- Test isolation: tests that call the processor directly left outbox rows PENDING; in a shared test database the relay processed them first and the BullMQ tests timed out. Those tests now retire their own tenants' rows (tenant-scoped update, nothing deleted).

## Not done / limits
- Slot-extraction accuracy, tool-selection accuracy, follow-up appropriateness as separate scores, p95 latency and cost per conversation are not computed. Locale quality is still `beta` (no native-speaker review). Scripted models test the code around the model, not the model's own behaviour; a live-model run needs an owner budget decision.
- The cases are generated by `eval/generate_phase7_cases.py`; wording per locale was written by the assistant and is not native-reviewed.
