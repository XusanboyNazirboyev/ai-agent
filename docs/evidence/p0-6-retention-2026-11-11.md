## What changed (scope)

- **Inbound events:** `RetentionService` (ScheduledScan) purges `PROCESSED|FAILED` inbound events where `expiresAt <= now`, and when `inboundEventMinutes` is configured also purges rows with `expiresAt IS NULL` and `receivedAt < now - minutes` (covers pre-P0.6 rows safely). Batched, tenant-scoped, idempotent.
- **Tenant retention settings:** parsed defensively from `tenants.retentionSettings` (`TenantRetentionSettingsSchema`); unknown/malformed values fail closed to "keep" (no purge). Optional `messageDays`/`conversationDays` trigger aged message/conversation purge with FK cleanup (tenant-scoped; see ADR 049 amendment).
- **Contact erasure (owner-initiated):** `DELETE /api/v1/contacts/:id` requires OWNER role; redacts contact PII (name/phone/language/script cleared, consent revoked, marketing opt-out, provider id replaced with non-reversible placeholder), sets `deletedAt`, redacts related messages/internal notes text and media refs, writes `audit_events` `contact.erased` (counts only, no PII). Idempotent for already-erased contacts. Erased contacts remain hidden by existing list filter.
- **No schema migration:** relies on existing `inbound_events.expiresAt`/index and `tenants.retentionSettings`/`contacts.deletedAt`; no additive migration added in this branch.
