# Slice 1 — scenario harness and v1 baseline (evidence)

Date: 2026-10-25. Branch `slice1/scenario-harness` (from `main` `45bf0a4`). ADR 026, roadmap slice 1. Synthetic data only; own database `agentcore_slice1`; no Redis, no ports, no Telegram; v1 code unchanged.

## What was built
- **Harness** (`apps/api/src/agent/testing/simulation/`):
  - scenario schema and loader
  - scripted customer and LLM-played customer
  - an isolated per-run world on the real v1 path (webhook → processor → agent pipeline → actions), with relay-like delivery and a shifted clock for follow-ups
  - deterministic grader, report against the frozen bar (pass^k), provider-failure triage, cost estimator
- **Scenarios** (`eval/scenarios/`, generated by `eval/generate_scenarios.py`):
  - education 30, tourism 10, retail 10
  - uz-Latn, ru and en for all, plus uz-Cyrl for 10 education scenarios: **160 scenario × language units**
  - wording not native-reviewed
- **CLI** `pnpm simulate` (opt-in `SIM=1`):
  - free presets for the dev loop
  - paid provider only with `SIM_PAID=1` and a budget of at most $5
  - refuses the dev database and `agentcore_test`
  - stops after 3 provider failures in a row
  - `SIM_ESTIMATE=1` gives the cost without any model call
- **Tests:**
  - unit (17): scenario counts and languages; the frozen thresholds must equal the roadmap table; the grader catches an invented price, a false success claim, another tenant's title and a wrong language; report pass^k; cost arithmetic
  - integration (5, real v1 pipeline with a scripted model): a grounded recommendation passes; a handover reason is checked; a confirmed action becomes a connector-confirmed lead; the follow-up clock; retail reported as not runnable

## How metrics are measured (deviations stated)
- **Goal completion is deterministic** (database state per scenario expectation: shown item, lead, proposal status, handover reason, follow-up). The roadmap row says "(judge)", but under amendment B the LLM judge does not gate until it is calibrated (≥ 20 human-graded conversations per language). Judge criteria are stored per scenario; no judge has run yet.
- **Invented facts:** every number of two or more digits in a business reply must be explained by the catalog, the customer's own text, the phone, or the locale's code-rendered templates. This is conservative, and the grader test proves it catches a false price.
- **Language and script:** the v1 lexical detector plus a letter-ratio script check. Replies shorter than 12 letters are skipped.
- **Scenarios are JSON** (Zod-validated), not YAML as the roadmap says: there is no YAML parser in the repository and the eval cases are already JSON.

## v1 baseline (dev loop, free model, NOT the gating baseline)
Model: Groq `openai/gpt-oss-20b` (FAST) / `openai/gpt-oss-120b` (STRONG); production v1 uses Claude Haiku on both tiers. Scripted customer, k = 1, synthetic data.

| Run | Units run | Passed | Goal | Correct handover | Language/script | Invented facts | False claims | Provider failures | p95 turn |
|---|---|---|---|---|---|---|---|---|---|
| education + tourism, en | 40 of 40 | 5 | 12.5% | 26.7% | 100% | 0 | 0 | 13 runs | 32.4 s |
| education, uz-Latn + ru | 6 of 80 (stopped: free quota) | 0 | 0% | 0% | 100% | 0 | 0 | 4 runs | 38.7 s |

**Triage of the 40 English runs:**
- 13 runs: provider failure (`LLM_UNAVAILABLE`; Groq strict-JSON 400s from `gpt-oss-20b`, or rate limits).
- 15 runs: guardrail handover. Violations: `FACT_NOT_LIVE` 14, `UNSOURCED_NUMBER` 13, `UNSOURCED_AVAILABILITY` 6, `UNSOURCED_CURRENCY` 4. The model typed prices or numbers instead of citing facts; v1 blocked every one and handed over.
- 12 runs: other.
- Turn outcomes: 31 of 47 turns ended in handover.

**What it shows about v1, independent of the model:**
1. **Safe by refusal:** 0 invented facts reached a customer, 0 false success claims, 100% language match. But most conversations end at the first failed draft, because the only recovery after one regeneration is a handover (audit root cause 6).
2. **A price shown through a live quote is not recorded** as a shown offer or quote, so v1's follow-up policy never fires after a price answer. This is pinned by an integration test.
3. **The travel pack has no high-value threshold**, so the "group of 12" scenario cannot hand over as `HIGH_VALUE` in v1.
4. **Retail is not runnable** (no pack; slice 3b, mock-only per decision 3): 30 units are counted as failed, not skipped.
5. Memory scenarios (`requires: memory`) run, but v1 has no cross-conversation memory.

What this is **not**: not a baseline of the production model, not k = 3, not all languages. The gating baseline needs the paid run below.

## Cost estimate for the paid gating baseline (owner decision 2)
Computed by `SIM_ESTIMATE=1` from the measured English report and `anthropic-2026-10-23` prices (Haiku $0.10/$0.50, Sonnet $2/$10 per MTok). Full suite = 130 runnable units × k = 3 = **390 runs**. No paid call has been made.

| Option | Measured shape (1.18 turns/run, 1,932 in / 610 out per turn) | Conservative bound (8 turns/run, 6,000 in / 800 out per turn) |
|---|---|---|
| A. v1 default (Haiku both tiers), scripted customer, no judge | $0.23 | **$3.12** (16 runs within $50) |
| B. A plus an LLM customer (Haiku) | $0.28 | **$3.46** (14 runs) |
| C. All agent tokens on Sonnet, LLM customer | $4.62 | $62.74 (exceeds the cap) |
| D. B plus a Sonnet judge (~3,000 in / 300 out per run; not gating) | $3.79 | $6.97 (7 runs) |

The measured shape is short because v1 hands over early; a healthier agent produces longer conversations, hence the conservative column. **Recommendation:** option A or B at k = 3, budget cap $5 per run (`SIM_BUDGET_USD=5`), after the owner approves. That needs an `ANTHROPIC_API_KEY`, which is not in the current `.env`.

## Other observations
- Groq smoke (2026-10-25): `openai/gpt-oss-20b` chat, tools and json_schema ok, 1.6 s.
- `pnpm llm:smoke <one provider>` **rewrites `docs/LLM_PROVIDER_STATUS.md` with only that provider's row**, deleting the others and the notes. It happened during this slice and the file was restored; the script should merge rows instead (not changed here).
- Free Groq limits (preset, *unverified*): 8,000 tokens/minute and 200,000/day. That is too small for full suites; the English run used about a third of a day's allowance.
- Client-side throttling longer than the turn timeout turns into `LLM_UNAVAILABLE` handovers. The CLI now caps the throttle wait at 20 s, below the 60 s turn timeout.
