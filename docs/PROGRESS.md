- **STUCK counts only the current dialogue (2026-10-26):** the live Gemini run showed `STUCK` firing on a plain greeting because the two latest committed no-progress turns of the conversation counted however old they were, and across human handovers. Now `selectEpisode` (core, pure) keeps only the unbroken run of earlier turns where every gap is at most `STUCK_WINDOW_MINUTES` (default 30) and that is newer than the end of the latest handover (`resolvedAt`, else `openedAt`); the conversation service passes it that run. Tests: unit (`stuck.spec.ts`) and three pipeline integration tests (same question inside one dialogue still escalates; a day-old run and a run before a finished handover do not), mutation-checked by restoring the old behaviour. The window length is a judgement call, not measured on real chats.
