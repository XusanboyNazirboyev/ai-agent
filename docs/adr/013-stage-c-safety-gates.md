# ADR 013: Pre-live safety gates (display evidence, language confidence, ambiguous usage)

- **Status:** Accepted (Stage C)
- **Date:** 2026-10-23

## Context
Stage B left four items open: listed prices could still be shown without a live quote, `LOW_LANG_CONFIDENCE` had a template but no trigger, Tier-0 rules and escalation were deferred ([ADR 012](012-provider-presets-and-failover-routing.md)), and a timed-out request was assumed unbilled. No `architect` subagent was available in this session (only generic agents), so the analysis was done directly from the code; this ADR is that memo.

## Decisions (where each responsibility lives)
- **Display gate: `core/agent/display-gate.ts`, called by `checkDraft`.** The turn already forces facts through `{{F<n>}}` references rendered by code. The gate verifies the stored evidence behind each reference; a model-written id proves nothing unless it resolves in this turn's `FactStore`. `FactProvenance` now carries `tenantId`, `conversationId`, `offerId`, `live`, stamped by `AgentTools` from the connector's own context and the turn scope (never from model output). A fact is rejected when: unknown; binding missing; tenant or conversation differs from the turn's (`FACT_SCOPE_MISMATCH`); a commercial fact names no offer; `validUntil` is past or within `minRemainingValidityMs` (10 s), or `retrievedAt` is older than `maxEvidenceAgeMs` (5 min) or in the future (`STALE_FACT`); or the connector can quote/check live but the fact is not from that live result (`FACT_NOT_LIVE`). "Required live" follows the connector contract: `capabilities.liveQuote` governs prices, `capabilities.availability` governs availability and seats; a connector without them may show unexpired listed data. Policy is `DisplayPolicy` (override via `AgentDependencies.displayPolicy`). The tool boundary already refused quotes/availability for another offer and expired live results; those tests stay. A typed availability phrase (the locale's own availability strings) outside a reference is `UNSOURCED_AVAILABILITY`. The number/currency checks remain a backstop, not the only mechanism.
- **Failure behavior.** Violations → one regeneration (existing) → re-check → `HANDOVER` with reason `GUARDRAIL` and `safety` = `{status:'ESCALATION_REQUIRED', gate:'DISPLAY', escalation:{reason:'GUARDRAIL', operatorNotified:false}}`. A draft rescued by the regeneration reports `safety.status = BLOCKED` for audit. The regeneration has no tools, so a listed price on a live-quote connector costs an extra call and ends in "an operator will confirm"; the system prompt already tells the model to call `get_quote`. No estimate is ever substituted. Code-side reconstruction of a richer reply from verified facts was considered and not built (more surface, no safety gain).
- **Language gate: `core/agent/language-policy.ts` + `safety.ts`, enforced in `runAgentTurn`.** Deterministic lexical detector (no extra model call, so nothing new to meter). `assessLanguage` returns language, script, supported locale and its status, the raw score, a confidence class (`HIGH/MEDIUM/LOW/NONE`), an ambiguity code, `method: 'lexical-heuristic'`, `calibrated: false`. The score is a heuristic, compared only with `LanguagePolicy` thresholds (HIGH: `stable 0.40`, `beta 0.45`, planned unreachable; MEDIUM 0.30; `maxUnclearTurns` 2; `modelCorroboration` per status). Two enforcement points:
  1. **Before any model call** (Tier-0): text mostly in an unsupported script (Arabic, CJK, …) → `CLARIFICATION_REQUIRED` (trilingual `languageClarification` template, slots untouched, zero spend), or `LOW_LANG_CONFIDENCE` escalation when the previous customer turn was already unclear.
  2. **Before commercial facts are looked up**: the reply locale needs evidence: this message is HIGH for it, the customer clearly wrote in it earlier (replayed from history, no new state), or the extraction model names it while the heuristic does not contradict it (never for mixed-script text). Otherwise clarify, then escalate. Slots extracted from an unreliable message are not kept; the history carries it.
  Slot questions and greetings are not gated (templates only). All four locales stay `beta`; the registry still refuses `stable` without native review. The beta threshold being only slightly stricter, and model corroboration being on for beta, are tunable defaults, not evidence of quality: **no live eval has measured detection accuracy**.
- **Tier-0 boundary.** Pre-model rules belong in `runAgentTurn` before `MeteredLlm`, never in the router. Implemented: the language hard stop. Router and failover cannot bypass it (a test asserts zero provider calls) and a test asserts the router imports no agent/locale/handover logic. Not implemented: other Tier-0 rules (e.g. keyword/PII/abuse screens): none is specified yet; owner layer = `core/agent` before step 1; pre-live acceptance = each new rule gets the same zero-call test.
- **Escalation representation.** `AgentTurnResult.safety` (`BLOCKED | CLARIFICATION_REQUIRED | ESCALATION_REQUIRED`, gate, reason codes, optional `escalation` with `operatorNotified: false`). The existing pipeline turns `outcome = HANDOVER` into a `Handover` row and `WAITING_OPERATOR`; notification to a person does not exist until Phase 5, and customer templates say only that the message was recorded. The router makes no operator or state decisions.
- **Ambiguous usage (timeouts).** A timeout may have been billed. `MeteredLlm` now (a) tells the provider `allowAmbiguousFailover` = whether the budget could also reserve a second worst-case call; the router fails over after `LLM_TIMEOUT` only if true (other failover errors are certainly unbilled and unchanged); (b) accounts every timed-out attempt as `usageBasis: 'unknown'`: cost 0 in persisted spend, worst case counted against the turn via `TurnBudget.addUnknownExposure`, entry id `unknown:<turnKey>:<callIndex>` (a retried job overwrites, no double count), encoded in `outcome = unknown_usage:<code>` so no migration is needed. Reported usage is `reported`, adapter-estimated usage is `estimated`. The router reports attempts via `ambiguousAttempts`. Persisted, atomic exposure accounting and the token budget moved to [ADR 014](014-atomic-llm-budget-reservations.md), which supersedes the usage-ledger based exposure and the `allowAmbiguousFailover` flag described above.

## Consequences
- Every connector that offers live quotes now needs a model that calls `get_quote`/`check_availability` before stating price/availability; eval and prompt quality for that are unmeasured live.
- Existing scripted eval cases that set `conversationLocale` now run with one establishing customer message in history (`ESTABLISHING_MESSAGES` in `eval-runner.ts`); their expectations are unchanged.
- `FactProvenance` and `AgentDependencies.scope` are required inputs for the gate; wiring a new caller without them fails typecheck.

## Not done / pre-live acceptance
Detection accuracy per locale, native-speaker review, and a live eval of the live-quote flow are required before `stable` and before any LIVE traffic. Operator notification is Phase 5.
