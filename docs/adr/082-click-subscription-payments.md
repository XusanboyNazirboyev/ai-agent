# ADR 082 — Subscription payments through Click (pay button, no automatic charging)

Status: accepted (2026-11-19). Implements ADR 047 §6 within ADR 080's owner decisions: no card storage and no automatic charging; the customer presses "Pay" each period and pays on Click's page. Owner choice 2026-11-19: Click (over Payme).

## Facts checked (official docs, read 2026-11-19)
The Shop API pages are rendered by JavaScript; their text was read from the site's own published page bundles (`/assets/js/f914dc4a.*.js` for `/shop-api/requests`, `/assets/js/44100f7c.*.js` for `/shop-api/errors`).
- **Pay link:** `https://my.click.uz/services/pay/?service_id={service_id}&merchant_id={merchant_id}&amount={amount}&transaction_param={transaction_param}&return_url={return_url}&card_type={card_type}`; `amount` in the format N.NN; `transaction_param` is our order id and comes back as `merchant_trans_id`; `merchant_user_id`, `return_url` and `card_type` are optional. <https://docs.click.uz/click-button>
- **Shop API:** Click calls the merchant's **Prepare** (`action = 0`) and **Complete** (`action = 1`) URLs with `POST`, `Content-Type: application/x-www-form-urlencoded`; the merchant answers JSON. <https://docs.click.uz/shop-api/requests>
  - Prepare fields: `click_trans_id` (bigint), `service_id` (int), `click_paydoc_id` (bigint), `merchant_trans_id` (varchar), `amount` (float, sums), `action`, `error`, `error_note`, `sign_time`, `sign_string = md5(click_trans_id + service_id + SECRET_KEY + merchant_trans_id + amount + action + sign_time)`. Answer: `click_trans_id`, `merchant_trans_id`, `merchant_prepare_id` (int), `error`, `error_note`.
  - Complete fields: the same plus `merchant_prepare_id`; `sign_string = md5(click_trans_id + service_id + SECRET_KEY + merchant_trans_id + merchant_prepare_id + amount + action + sign_time)`. Answer: `click_trans_id`, `merchant_trans_id`, `merchant_confirm_id` (int), `error`, `error_note`. After repeated error answers Click may put the payment into manual review by its support.
- **Merchant error codes:** 0 Success, −1 SIGN CHECK FAILED, −2 Incorrect parameter amount, −3 Action not found, −4 Already paid, −5 User does not exist (merchant_trans_id), −6 Transaction does not exist (merchant_prepare_id), −7 Failed to update user, −8 Error in request from click, −9 Transaction cancelled. <https://docs.click.uz/shop-api/errors>
- Not verified against Click's test environment or a live service: everything above; the owner's merchant contract is required first.

## Decision
- **Tenant side:** Settings → Subscription (OWNER/ADMIN) shows plan, state and period end, a plan choice from the active public plans (current plan preselected), and "Pay with Click". `POST /api/v1/billing/click/checkout { planCode }` creates a `subscription_payments` row (`CLICK`, `PENDING`, amount = plan price) and returns the pay link with `transaction_param` = that row's id and `return_url` back to the subscription page. Amount is rendered by code from minor units. Hidden when Click is not configured.
- **Click callbacks:** `POST /api/v1/payments/click/prepare` and `/complete`, public, form-encoded, no session. Every request: required fields present (else −8), `service_id` equals ours (else −8), signature checked in constant time (else −1), `action` matches the endpoint (else −3), payment found by `merchant_trans_id` (else −5), amount equal to the stored amount in minor units (else −2), payment already `PAID` (−4) or cancelled (−9). Prepare records Click's ids and answers a numeric `merchant_prepare_id`; Complete with `error < 0` from Click marks the payment failed and answers −9; otherwise, in one transaction, marks it `PAID` with `paid_at`, extends the open subscription by the plan period or starts an `ACTIVE` one (from `TRIAL`, `PAST_DUE` or `EXPIRED`, switching to the paid plan), writes a platform audit event and answers a numeric `merchant_confirm_id`. A repeated Complete is answered from the stored outcome (idempotent; never extends twice).
- **Storage:** a `click_transactions` table (numeric identity id used as `merchant_prepare_id` / `merchant_confirm_id`, tenant, payment, `click_trans_id` unique, `click_paydoc_id`, state, timestamps) with an RLS tenant policy; the callback finds the payment without a tenant on the privileged connection, then works inside that tenant's context. `safe_summary` keeps only ids and state, never raw payloads.
- **Secrets:** `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_SECRET_KEY`, optional `CLICK_MERCHANT_USER_ID` in the server's secret store; never logged or returned.

## Owner steps
Sign the Click merchant contract; put the four values into the server's secret store; in the Click merchant cabinet set the Prepare URL to `https://<api host>/api/v1/payments/click/prepare` and the Complete URL to `…/complete`; enter plan prices in the console.

## Not done
Payme; card storage and automatic charging (owner decision); refunds through `payment/reversal`; fiscal receipts (Click fiscalization); invoices.
