# Universal-agent roadmap and ordered remediation — 2026-11-06

## Preserve and extend (do not recreate)
Current code already has education and travel packs, canonical connector capabilities/conformance, Telegram and Instagram paths, knowledge retrieval, lead scoring/follow-up, confirmed action proposals, handover/inbox, typed fact provenance, and a scripted/lifecycle eval gate. Instagram's existing connect path is not being replaced; the old “Invalid platform app” report is not treated as a current bug. Live Meta behavior remains unverified.

## Remediation status and remaining ordered backlog
1. **Auth/session containment (AUD-15, AUD-05, AUD-03) — implemented in worktree:** open SSE streams close on logout/revocation/expiry/idle expiry/deactivation; failed-attempt counting and lock transitions are atomic; password changes revoke active sessions. Focused API integration tests passed. No OAuth or DB migration changes.
2. **Operator context correctness (AUD-01, AUD-02):** align waiting-order query and cursor; add stable timeline pagination/window semantics. Scope: inbox read API/types/UI and tests for interleaved pages plus 550+ messages.
3. **Fact-safety and catalog independence (AUD-09, AUD-10):** route knowledge-only turns without a catalog connector and make fallback titles pass provenance/display checks. Scope: pack/tool capability contract, agent turn, guardrail tests; preserve existing safety gates.
4. **Draft isolation (AUD-11):** bind completion/reset behavior to the submitted conversation and draft version. Scope: inbox component plus delayed-response browser regression.
5. **Stream/process resilience (AUD-08, AUD-06, AUD-12):** bound SSE backpressure, validate event payloads, and verify graceful worker/DB shutdown. Scope: stream unit/integration tests and controlled SIGTERM test.

Auth/session containment was implemented in the uncommitted worktree, including the conditional AUD-03 session revocation behavior. Targeted API integration (60 tests) and policy/startup unit (24 tests) passed; typecheck, lint, and build passed. The change has not been committed or deployed. The Instagram LIVE-without-Telegram-group change is separately documented in [ADR 031](../adr/031-instagram-dm-channel.md). Items 2–5 remain unimplemented; only the audit's presented security findings and the user's Instagram request were authorized. No real channel, CRM write, paid model, commit, push, or deploy was used.

## Universal acceptance plan
- Keep the core unchanged while exercising three materially different domain configurations: existing education, existing travel, and one third synthetic domain selected before implementation.
- Test separately: knowledge-only support with no catalog connector; catalog sales; lead capture with no catalog connector; live quote/availability; explicit business-action proposal/confirmation; human handover.
- Include multiple connector roles (catalog/read, live quote/availability, lead/write) with two active candidates, failure/fallback, and tenant-isolation cases. Selection must be explicit, not insertion-order dependent.
- Gate on no `apps/api/src/core/**` changes for onboarding after capability support is established; run conformance and end-to-end flows per tenant in one process.

## Real-model evaluation plan (not authorized/run)
- Synthetic cases across uz-Latn, uz-Cyrl, ru, en: greeting, FAQ, catalog, quote, lead qualification, ambiguity, objection, tool failure, prompt injection, and handover.
- Score task success, fact correctness, false blocks, unnecessary handover, language/script match, tool correctness, false success claims, latency, and cost/success. Safety has zero-tolerance gates; quality/performance targets are separate.
- Use deterministic checks plus calibrated human/native-speaker review; an LLM grader is never the sole oracle. Set sample size, model/provider, time/cost cap and owner approval before any live call.
